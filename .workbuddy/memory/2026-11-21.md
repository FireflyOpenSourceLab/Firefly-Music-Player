  - 布局：外层 `div().flex().flex_col()`，标题栏在 `SidebarLayout` 之上（标题栏容器套在 sidebar 上）。
- 平台判断用运行时 `cx.platform_info().is_mac()`（Context deref 到 App）。

## 应用图标生成

- 源图 `assets/icon/icon.png` 只有 **100×100**，放大到 1024 会明显发虚，理想是提供 ≥1024 的源图再重跑脚本。
- 生成脚本 `scripts/gen_icons.py`（纯标准库 + 系统 `sips`/`iconutil`，无需 Pillow）：
  - `assets/icon/png/icon_{16,24,32,48,64,128,256,512,1024}.png` — 由 1024 母版向下缩放，避免累积误差。
  - `assets/icon/AppIcon.icns` — 经 `AppIcon.iconset`（10 档）→ `iconutil -c icns`。
  - `assets/icon/icon.ico` — 手写 ICO 容器，内嵌 7 档 PNG（16/24/32/48/64/128/256，256 尺寸在目录项记作 0），Vista+ 原生支持 PNG 压缩条目。
- 项目目前没有 bundler 配置（无 cargo-bundle / Tauri），图标尚未被任何打包流程引用。
- 另出 `assets/icon/AppIcon-padded.icns`：按 macOS 图标网格把主体缩到 824、居中放进 1024 透明画布（`sips` 不支持透明 pad，脚本内置极简 PNG 读写自己合成）。原 `AppIcon.icns` 保持无留白。

## 全局字体换成 HarmonyOS Sans

- `assets/fonts` 下的 Geist 已被替换成 5 个字重的 HarmonyOS Sans，`app.rs::bundled_fonts()` 原本用 `include_bytes!` 硬编码 Geist 路径，不改会直接编译失败。
- 族名：`HarmonyOS Sans`（Light 300 / Regular 400 / Bold 700 同族）；`HarmonyOS Sans Thin`(250) 与 `HarmonyOS Sans Black`(900) 在字体内部是**独立族名**，按 weight 900 只会落到 Bold。
- 字体只含 874 个码位、**无任何中文字形**，中文靠系统回退（macOS → PingFang SC）渲染。之前 Geist 同样没有中文、回退正常，故机制已验证。若要中文也是 HarmonyOS 风格需补 `HarmonyOS_Sans_SC.ttf`。
- 字体名统一在 `src/ui/app_theme.rs` 的 `BODY_FONT` / `MONO_FONT` 常量中定义，`theme()` 里写进 `UiFonts`；`UiTheme::set` → `sync_component_theme` 会把 `font_family`/`mono_font_family` 同步给 gpui-kit 组件。
- 全局生效靠 `Player::render` 根 div 上的 `.font_family(theme.fonts.body)`（gpui 沿元素树继承）。

## 主窗口最小尺寸 900×600

- `WindowOptions.window_min_size: Some(size(px(MIN_WINDOW_WIDTH), px(MIN_WINDOW_HEIGHT)))`，常量定义在 `main.rs` 顶部。演变：800 → 640（为了能拖到 700 以下）→ **900**（用户最终要求）。
- 最小宽度最终定为 **900**；侧边栏收缩阈值后调整为 **950**，所以最小宽度也落在收缩区间内。
- 三平台后端都消费该字段：macOS `setContentMinSize`（gpui-pre-macos window.rs:1194）、Windows `min_size`（window.rs:536）、Linux X11/Wayland 各自的 min size 设置。macOS 上是**内容区**最小尺寸，我们的标题栏画在内容区内，所以整窗高度也一起被约束。

## 侧边栏 ≤950 自动收缩成图标栏

- 阈值 `SIDEBAR_COLLAPSE_WIDTH = 950.`（最初 700，随最小宽度 900 上调） + `sidebar_narrow(width)` 判定，`main.rs` 底部有边界单测。
- **不改写用户偏好**：渲染时派生 `layout_state = SidebarState { open: self.sidebar.open && !narrow, .. }` 传给 `SidebarLayout`；窗口变宽后自动恢复成用户先前选择的状态。
- `SidebarLayout` 默认 `SidebarCollapsible::Offcanvas`（收起=整栏隐藏），必须显式 `.collapsible(SidebarCollapsible::Icon)` 才是图标栏。
- **库不会把折叠状态下发给条目**：`SidebarItem` 的 `collapsed` 字段默认 false，必须逐个 `.collapsed(bool)`，否则图标栏里仍会画文字被裁。
- 已移除 layout 的 mobile 抽屉模式（`mobile` 断点 768 会让 701–767 变成整栏消失，而本项目标题栏没有抽屉触发按钮）；窄宽度统一由图标栏承接，`now_playing_panel` 也不再随宽度隐藏。
- 收缩期间 `on_change` 直接 return，避免布局把 `open` 改回 true 冲掉偏好。图标栏条目宽 32px（侧栏 48 − 内容区左右各 8 的 padding），条目内左右各 8 的 padding 只剩 16px，图标要从 5 个 spacing 单位缩到 4（16px）才不被裁。
- 窗口 resize 会走 `Window::bounds_changed` → `refresh()` 重渲染，所以 `narrow` 能实时跟随，不需要额外监听。

## 右侧「正在播放」面板

- 新增 `src/ui/now_playing.rs`：纯数据模型（`Track` / `NowPlaying` / `RepeatMode` / `LYRICS`），含 6 个单测（`cargo test --bin FireflyMusic now_playing`）。进度用**归一化 0..=1** 而非秒数，切歌时不必重建进度条状态。
- 视图在 `main.rs::now_playing_panel`，挂在 content 右侧：`content_row = div().flex().child(content.flex_1().min_w_0()).when(!mobile, panel)`。侧边栏默认 `SidebarVariant::Sidebar`（非 Inset），content 无外边距，面板能贴到窗口右缘。
- 进度条是自绘轨道（`relative()` 百分比 + 内嵌滑块），交互交给**透明叠加层**：`Slider` + `SliderTrack` + `SliderIndicator`（`gpui_kit::base::slider`）。`SliderIndicator` 是唯一往 `SliderState.bounds` 写值的地方，缺了它点击定位会失效。
- 进度同步：滑动 → `SliderEvent::Change` → 写回 `now.progress`；切歌/上一首后用 `set_value(progress, window, cx)` 回写，避免下次拖动从旧值起算。
- 播放计时用 `cx.spawn_in` 每 250ms 推进，靠 `tick_generation: u64` 代次号让旧任务自行退出（不保存 `Task`）。
- 曲目/歌词为演示数据（`Firefly Studio`），接真实音频时替换 `now_playing.rs` 的播放源即可。
- **2026-11-22：面板内容已按要求全部清空**，`now_playing_panel` 只剩 300px 空白底板（`sidebar` 底色 + 左边框）。`NowPlaying` 模型、`Player.now` / `seek` 状态、`round_button` / `set_playing` / `start_ticker` / `sync_slider` 均保留未删（`#![allow(dead_code)]` 兜底），随时可恢复视图；同时移除了随之无用的 `Slider`/`SliderTrack`/`SliderIndicator`/`RepeatMode`/`relative` 导入。

## 环境限制（重要）

- 沙箱内 `screencapture` 报 `could not create image from display`，放开沙箱也一样 → **无法截图验证 UI**，只能靠编译 + 运行无 panic + 代码路径确认。
- `osascript` 查询窗口尺寸被拒（权限违例 -10004），无法验证窗口几何。
- **磁盘几乎占满（228G 里只剩百余 MiB）**，`cargo test` / 链接会报 `No space left on device`。删 `target/debug/incremental`（约 100M）可临时缓解；空间恢复后 `cargo build` 正常。以后遇到链接失败先看 `df -h`。
