## 修复浮动栏按钮点击 panic + 音乐库双栏（23:5x）

### panic 修复（重要）
- 现象：点浮动栏的循环/上一曲/播放/下一曲立刻 crash（exit 134）：
  `cannot read FireflyMusic::Player while it is already being updated`（entity_map.rs:184）。
- 原因：`cx.listener` 的闭包在 `update_entity` 里执行，此时实体仍被独占借用；
  在里面直接 `tray_menu::refresh(cx)` 会重建菜单 → 读 `WeakEntity<Player>` → 二次借用 panic。
- 修法：`cx.defer(|cx| tray_menu::refresh(cx));` 推到本轮 effect 之后。
  **规则：任何 listener 内部都不要同步 read 自己这个实体**（托盘安装当初也是同样原因用 defer）。

### 音乐库改成左右两栏
- `LibraryFolders` → `LibraryState { folders, selected, files, scanning, generation }`，
  仍是全局状态（页面是无状态 `view(cx)`，改完靠 `cx.refresh_windows()` 重绘）。
- 左栏 208px：`文件夹` 标题 + 右上角 FolderPlus 小按钮；每行 34px，选中 `muted` 底 + FolderOpen 图标，
  未选中 Folder 图标 + 悬停变深；点击 `select_folder()` 切选中并重扫。
- 右栏：标题行（文件夹名 + `N 首 · 扫描中…`）+ 歌曲列表，行高 44：
  序号(24px 右对齐) / FileMusic 图标 / 标题 + 艺人 / 右侧 `MP3 · 4.2 MB`。
- 扫描：`scan_folder()` 递归（深度 ≤8、上限 5000 首），扩展名白名单

  运行在 `cx.background_executor()`，结果回主线程前比对 `generation`，切文件夹时旧结果自动作废。
- 空态分支保留：没有文件夹时仍是「还没有音乐哦 + 添加文件夹」。
