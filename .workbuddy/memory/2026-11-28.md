## 修复：拿不到歌曲总时长（浮动栏永远 `--:--`）

根因：`audio::open_sink` 只读 rodio `Decoder::total_duration()`，而 symphonia 的时长
= `codec_params.time_base.zip(n_frames)` —— 没有 Xing/Info 头的 CBR mp3、裸 ADTS AAC
这两项都缺，直接给 `None`，代码里落到 `0.`，于是总时长显示 `--:--`、
`seek_progress` 直接 return（进度条也废）。

实测（`~/Music/.../0922.mp3`、`Documents/测试音源/1124.MP3`）：
decoder = None / None，lofty = 177.659s / 147.069s；`Level up.mp3` 有 Xing 头，两边都正常。

修法：
- `services::tags::duration_seconds(path)`：lofty 读容器头算时长（mp3 无 Xing 时按
  比特率 × 数据长度估算），只读文件头不解码。
- `audio::pick_duration(from_decoder, from_header)`：解码器优先，拿不到（None/0/NaN）
  才走闭包去读文件头，避免每首歌都白解析一遍标签（含内嵌封面）。
- `NowPlaying.duration` 注释更新为「解码器与容器头都给不出时才是 0」。

测试：新增 `duration_falls_back_to_container_header`、`reads_duration_from_the_container`、
`duration_is_none_when_unreadable`；全量 91 项通过，`cargo build` 仅剩 ui/dialog.rs
既有的 `DialogChangeReason` 未使用警告。

## 修复：当前播放位置永远不动（计时器启动即自杀）

根因：`audio::start_ticker` 用 `tick(cx)` 的 bool 返回值当「App 是否还活着」：

```rust
if !cx.update(|cx| tick(cx)) { break; }
```

而 `tick` 在「没有队列 / 没有输出设备 / 位置没变」时都返回 `false`（本意是「这一拍没变化」）。
`audio::init` 在 `Player::new` 里调用，此时队列必然是空的 → 250ms 后第一拍就
`return false` → 循环 `break`，`ticker_started` 已经是 true 不会重启。
结果：位置永远 0、进度条不动、放完不自动下一首（`sink.empty()` 再也检测不到）。

修法：
- `tick` 改为返回 `()`，注释写明「没事干 ≠ App 关闭」。
- 循环无限转，不再自己判断退出（任务随 App 的 executor 一起销毁）。

回归测试 `audio::tests::ticker_survives_an_idle_start`（`#[gpui_kit::test]`）：
`init` → `advance_clock(8 拍)` 走过空闲 → 塞两首 + `playing=true` 且没有 sink 的假状态
→ 再推一拍 → 断言 `index` 从 0 变 1（只有 tick 里的 `advance` 会挪下标）。
已验证：换成旧的 break 写法后该测试确实失败（index 仍 0），改回来通过。
全量 92 项通过。

## 进度条只能往后点、回跳无效（2026-11-28 14:20）

根因在 rodio，不在 UI：`Decoder::new_mp3/new_mp4/…` 内部只走
`DecoderBuilder` 的默认 `Settings`（`byte_len = None`、`is_seekable = false`），
`symphonia` 拿不到字节长度就只能往前读，往回 seek 直接返回
`ForwardOnly` → rodio 包成 `RandomAccessNotSupported`，界面看着就是「时间点越点越往后，往回点没反应」。

- `audio.rs::open_sink`：打开文件后先取 `metadata().len()`，把 `byte_len` 交给解码器。
- `audio.rs::decoder_for(reader, byte_len, path)` 改为用
  `DecoderBuilder::new().with_data(..).with_byte_len(len)` 构造
  （`with_byte_len` 顺带把 `is_seekable` 置真）；扩展名 → 提示改成 `probe_hint()`：
  mp4 家族给 `with_mime_type("audio/mp4")`，其余给 `with_hint(ext)`，认不出的交给内容探测。
- `seek_seconds`：`try_seek` 失败时不再改 `position`（否则界面先跳、下一次 tick 又弹回，
  像「闪一下没反应」）。
- 测试：`decoder_seeks_backwards`（无设备，前进后再回跳）、
  `probe_hints_cover_the_known_families`、`clicking_earlier_on_the_progress_line_seeks_back`
  （UI：先点 3/4 再点 1/4），以及 `#[ignore]` 的 `sink_reports_a_backwards_seek`
  （真设备，回跳后等 200ms 让音频线程回写位置）。108 项通过、`--ignored` 5 项也通过。
- 反证过：把构造改回 `Decoder::new(...)`，设备级回跳用例立刻失败。
