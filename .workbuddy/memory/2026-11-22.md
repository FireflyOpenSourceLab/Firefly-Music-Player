# 2026-11-22

## 系统托盘（gpui-tray 0.3）

- 依赖：`gpui-tray = { version = "=0.3.0", default-features = false, features = ["gpui-kit", "menu-state"] }`。
  `gpui-kit` 后端依赖 `gpui-pre ^0.3.4`，与项目现有 `gpui-pre 0.3.12` 同源，`App`/`MenuItem`/`Action` 类型天然统一。
- 新模块 `src/tray_menu.rs`：
  - `actions!(firefly_tray, [TrayNoop, TrayNext, TrayPrevious, TrayTogglePlay, TrayOpenWindow, TrayToggleLoop, TrayQuit])`；
  - `TrayModel { track: Option<String>, playing, looping }`，`label()` 在无媒体时返回「无媒体」；
  - 菜单顺序：曲目（disabled）/ 分隔 / 下一曲 / 播放·暂停 / 上一曲 / 打开主面板 / 循环播放（checked）/ 分隔 / 退出；
  - `install(cx, WeakEntity<Player>)` 把 `Tray` 与状态读取闭包挂进 `Global`（`TrayHandle`），另有 `refresh(cx)` / `close(cx)`。
- 托盘图标：`scripts/gen_icons.py` 新增 `build_tray()`，从源图直接缩出裸 RGBA
  （`assets/icon/tray-36.rgba` macOS 36px@2x、`tray-32.rgba` 其他平台），
  `include_bytes!` 后交给 `Icon::from_rgba`，运行时不解码 PNG。
  `read_png()` 同时支持 color type 2/6（sips 对无透明图会输出 RGB）。
- **坑 1**：`Context` 自带 `on_action`（绑窗口，多 TypeId/Window 两个参数），会遮蔽 `App::on_action`。
  在 `Context` 里注册应用级动作要先 `let cx: &mut App = cx;`。
- **坑 2**：`Tray::build` 会立刻调用菜单构建闭包，闭包读 `Player` 实体；若在 `Player::new` 里直接装，
  会 panic `cannot read Player while it is already being updated`。改用 `cx.defer(...)` 推迟到本轮 effect 之后。
- 验证方式（沙箱无法点托盘）：临时加调试输出 + `cx.defer(|cx| cx.dispatch_action(&TrayToggleLoop))`，
  确认 `[debug] 循环模式 -> All`（Off→All）且 `refresh` 无报错，随后移除调试代码。
- 行为：`下一曲/上一曲/播放暂停/循环` 直接改 `Player.now`；「打开主面板」= `cx.windows()` 取首个窗口
  `window.activate_window()` + `cx.activate(true)`；「退出」= `tray_menu::close` 后 `cx.quit()`。
- 菜单文案是动态的：暂停时显示「播放」，播放中显示「暂停」（用户原话只列了「暂停」）。

## 右侧面板 → 内容区底部浮动栏（23:0x）

- 删除 `now_playing_panel()` 与 `NOW_PLAYING_WIDTH`（353px 右侧面板），右侧栏不再占位。
- `render()` 里内容区改为 `page`（`.flex_1().relative()`），占满右侧；浮动栏作为其绝对定位子元素。
- 新增常量：`FLOAT_BAR_HEIGHT=20`、`FLOAT_BAR_RADIUS=35`、`FLOAT_BAR_INSET_X=120`、`FLOAT_BAR_INSET_BOTTOM=12`。
  浮动栏样式：`.absolute() .left/right(120px) .bottom(12px) .h(20px) .rounded(35px)`，
  `bg=sidebar`、`border=sidebar_border`、`shadow=sm`，内容留空待接播放控制。
- 注意：`.rounded(35)` 大于高度一半（10），渲染器会压成胶囊，属预期。
- 后续调整：浮动栏高度 20 → **70px**（`FLOAT_BAR_HEIGHT=70`，圆角 35 恰为高度一半，正好是标准胶囊）。

## 去掉标题栏与 sidebar 之间的边界（次日 00:0x）

- 自绘标题栏原来是通栏 `.border_b_1()`（`sidebar_border`），这条线也横跨 sidebar 上方，形成分隔感。
- 改法：标题栏去掉底边；把分隔线移到内容区 `page` 的上边框（`.border_t_1()`），
  这样 sidebar 与标题栏同色同面、连成一体，而内容区仍与标题栏有清晰分界。

## 页面显示区左上角 20px 圆角（次日 00:0x）

- 新增 `PAGE_CORNER_RADIUS=20`；`page` 加 `.rounded_tl(px(20.))` + `.overflow_hidden()`（防止子元素直角铺色盖掉弧）。
- 内层 `content` 去掉 `.bg(background)`，底色统一由带圆角的 `page` 提供。
- `content_row` 底色改为 `sidebar`（与侧边栏/标题栏同色），作为圆角缺口露出的外壳色，弧线才看得出来。
- 可用 API 提示：`rounded_tl/tr/bl/br`、`rounded_t/b/l/r` 均由 `gpui-pre` 的 Refineable 派生宏生成（见 gpui-pre-macros/src/styles.rs `corner_prefixes()`）。

## "残余边界线"排查（次日 00:07）

- 现象：用户说标题栏与 sidebar 之间仍有边界线。检查代码确认标题栏已无 `.border_b_1()`，
  sidebar 根节点也没有上边框（`sidebar.rs` 只在非 padded 模式给右侧 `border_r_1`），两侧底色同为 `colors.sidebar`。
- 真因：用户看的是**旧进程**（pid 29896，二进制在改动前的 00:02 构建），标题栏底边还在。
- 处理：`cargo build` 重新编译 → `kill 旧 pid` → 后台启动 `./target/debug/FireflyMusic`（pid 30976）。
- 教训：改完界面若只跑 `cargo check`，用户手里的窗口不会更新（macOS 上覆盖二进制后旧进程仍跑旧 inode）。
  以后交付 UI 改动应顺手 `cargo build` 并重启实例。
